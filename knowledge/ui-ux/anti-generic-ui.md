# Anti-Generic UI

The goal is not to ban popular patterns.

The goal is to prevent agents from choosing patterns automatically.

## Generic-agent signature

A UI is at risk when several choices are simultaneously interchangeable with thousands of unrelated products.

Common signals:

- centered marketing hero with a small badge above it
- generic gradient words inside the main headline
- two CTA buttons regardless of actual conversion hierarchy
- repeated icon-circle feature cards
- identical three-column sections
- bento grids with no information-architecture reason
- floating product screenshot inside a glowing frame
- purple/blue cyan glows used as generic "AI" branding
- translucent glass panels on every surface
- huge radii and pills everywhere
- every section placed in a separate card
- excessive shadow/elevation
- stock "AI" grids, dots, blobs, or orbital graphics
- faux command palettes or terminal windows used decoratively
- fake dashboards with meaningless charts
- invented logos/testimonials/usage counts
- overuse of tiny uppercase eyebrow labels
- enormous headline followed by vague copy
- feature copy that could describe any SaaS product
- identical fade-up animation on every section
- excessive scroll-triggered reveals
- monochrome dark UI with neon accent by default
- needless gradient borders
- decorative 3D objects with no brand relationship
- using the same component radius, padding, and density for every content type

## The replacement process

Do not merely remove a generic pattern.

Ask what job it was attempting to do.

```text
Need hierarchy?
Use hierarchy.

Need trust?
Use evidence, clarity, typography, and restraint.

Need brand recognition?
Use a specific brand motif.

Need visual interest?
Use one contextual signature.

Need grouping?
Use spacing, alignment, borders, or surfaces.

Need emphasis?
Use contrast and position before glow.

Need explanation?
Use meaningful diagram or content.

Need delight?
Use one intentional interaction or motion moment.
```

## Product-specificity test

Ask:

1. What visual decision comes from this product's actual content?
2. What comes from its audience?
3. What comes from its trust/risk profile?
4. What comes from its brand?
5. What comes from its primary workflow?
6. What would be meaningfully different if this were another product?

If the answers are mostly "nothing," the interface is generic.

## Context beats bans

A dashboard may need cards.

A premium campaign may need a gradient.

A real layered surface may benefit from translucency.

A complex product may benefit from bento-like grouping.

A system font may be exactly right for an operational tool.

The standard is not novelty.

The standard is intentionality.
