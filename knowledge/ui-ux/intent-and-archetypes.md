# Intent and Product Archetypes

Archetypes are starting priors, not templates.

A product's actual user, task, risk, brand, and existing system always win.

## Enterprise / operations

Typical priorities:

```text
clarity
speed
predictability
density
keyboard efficiency
status visibility
auditability
error prevention
```

Common direction:

- restrained to considered creative latitude
- compact or balanced density
- subtle motion
- familiar controls
- strong information hierarchy
- explicit statuses and consequences

Distinctiveness should come from precision, information design, brand details, and workflow quality rather than decorative spectacle.

## Finance / healthcare / regulated

Typical priorities:

```text
trust
accuracy
legibility
consequence visibility
accessibility
privacy cues
error prevention
recovery
```

Use restraint unless the product context justifies otherwise.

Never imply safety, certainty, compliance, or outcomes that are not supported.

## Developer tools

Typical priorities:

```text
density
keyboard flow
fast scanning
clear hierarchy
status/log visibility
copyable technical content
stable layout
```

Monospace can be useful for code, identifiers, metrics, and tabular values, not necessarily for all UI text.

Visual personality can come from technical precision, color semantics, information architecture, and focused signature details.

## SaaS / general product UI

Typical priorities:

```text
task clarity
learnability
moderate density
consistent navigation
clear states
brand recognition
```

Default to considered creative latitude and subtle motion unless context suggests otherwise.

Do not default to generic marketing-page aesthetics inside the product application.

## Marketing / launch

Typical priorities:

```text
message
differentiation
brand
attention
conversion
narrative
proof
```

More expressive composition, typography, imagery, and motion can be appropriate.

Do not invent social proof.

Do not let spectacle hide the proposition or CTA.

## Portfolio / creative studio

Typical priorities:

```text
identity
memorability
craft
work presentation
narrative
```

Expressive or experimental design can be valid.

Interaction fundamentals and content access still matter.

## Editorial / documentation / blog

Typical priorities:

```text
reading comfort
content hierarchy
navigation
search
code/media readability
long-form rhythm
```

Typography and width often matter more than decorative surfaces.

Avoid excessive cards that fragment reading.

## Commerce

Typical priorities:

```text
product clarity
comparison
price
availability
trust
checkout progression
mobile usability
```

Use imagery and hierarchy to support product evaluation.

Do not let branded effects obscure purchase-critical information.

## Data / analytics

Typical priorities:

```text
comparison
trend recognition
context
filtering
data density
stable scales
accessible encoding
```

Use color as one channel, never the only channel.

Favor meaningful chart choice over decorative dashboards.

## Consumer / social

Typical priorities:

```text
mobile
content
speed
feedback
discoverability
identity
```

Motion can be more expressive, but high-frequency interactions must remain fast.

## Calibration matrix

| Context | Creative latitude | Motion | Density |
|---|---:|---:|---|
| Admin/ops | 0–1 | 0–1 | compact |
| Regulated | 0–1 | 0–1 | balanced |
| Developer tool | 1 | 0–1 | compact |
| SaaS app | 1 | 1 | balanced |
| Editorial | 1–2 | 0–1 | spacious |
| Commerce | 1–2 | 1 | balanced |
| Marketing | 2 | 1–2 | spacious |
| Portfolio | 2–3 | 1–3 | variable |
| Campaign/experimental | 3 | 2–3 | variable |

Treat the table as a prior, never an automatic answer.
