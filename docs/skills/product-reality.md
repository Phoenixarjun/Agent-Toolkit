# Product Reality

`/product-reality` is an evidence-aware product thesis review. It asks whether a specific product delivers a real outcome, why its intended users would choose it over alternatives, and what could weaken that value over time.

It is **not** a generic startup idea generator, market-sizing service, code review, security audit, specification writer or AI-content detector.

## When to invoke

Use it before investing in a product, when a feature's customer value is unclear, when an AI-based app may be easily substituted, when an incumbent ships a similar feature, or when deciding whether an existing product should continue, change audience, validate demand or stop.

Example:

```text
/product-reality
Assess this existing product for its stated users and current stage.
Challenge its real customer value, substitute options, and dependency on
an AI provider. Prefer no new features unless evidence supports them.
Return the smallest decision-changing experiment and explain what not to build.
```

## How it reasons

Reality → Purpose → Structure → Leverage → Consequences → Evolution is a product judgment sequence, not a six-stage documentation bureaucracy. It compares actual customer outcomes with current alternatives, tests the difference between easy-to-copy code and replaceable value, challenges uncertain numbers, and evaluates how the product should respond when the market changes.

Its default is **one agent, no mandatory interrogation or research**. GrillMe is optional for consequential creator-owned unknowns, with a shared limit of eight questions maximum. Research is optional when real external evidence would change the verdict; Focused or Standard is preferred over Deep for ordinary product questions. One independent critic is optional only when cost, irreversibility or dispute justifies it and true isolated context exists.

## Output

The Product Reality Report provides a short verdict, its evidence basis, relevant substitutes and differentiation, material risks, what is sufficient as-is, up to three actions, a falsifying experiment and reassessment signals. It never invents a market-size or AI-slop score, guaranteed ROI, paying users or platform roadmap.

## Boundaries

Problem to Solution selects solution mechanisms; Product Reality tests a particular product thesis. App Check audits technical health. Code Explore maps code impact. `/code` implements changes. Product Reality can recommend that one of these capabilities be invoked, but does not silently inherit their authority.

The canonical procedure is [the skill](../../skills/product-reality/SKILL.md). The evidence-and-substitution reference is loaded only for deeper claims. Reports are not a substitute for real customer observation or paid commitments, and defined evals are not measured agent performance.
