# Content and platform decision guidance

Optimize credible professional evidence, not vanity metrics. A candidate may decline public presence, publish rarely, or have private work. Derive target audience (recruiter, technical peers, customers, hiring manager), candidate voice, purpose and platform from actual preferences. Profile optimization and publication preparation are separate. Keep shared facts, separate presentation.

## Platform lenses

LinkedIn: audit current headline, About, experience, skills, projects/Featured, links and optional activity. Verify current platform constraints when needed; do not invent a character limit or claim algorithmic reach. Select only relevant accessible sections. Headline and About explain role/domain/value; experience establishes evidence and ownership; skills/Featured link actual work. Provide exact replacement and reason per changed section. Avoid keyword stuffing, engagement bait, inflated title and repetitive copy. For public posting, preserve candidate voice and distinguish commentary from original research.

GitHub: verify public ownership and authorized repo scope, distinguish forks/contributions and authored work. Audit profile README, pinned repos, relevance, README/setup, architecture, tests, issues/releases and actual code if scoped. `code-explore` can inspect implementation and `code-review` can assess code where authorized. No commit, push or rewrite by default. Do not reward activity streaks without substance. Give prioritization and ready-to-use README/pin suggestions; note unrun tests.

Medium/blog: choose a clear technical question and audience; prioritize explanation, tradeoffs, actual experiments and sources. Use an outline and an approved writing mode; preserve authentic voice, avoid AI marketing prose, don't assert authorship/experiments not done. Distinguish draft illustrations, verified code outputs and conceptual diagrams. For Kaggle/LeetCode evaluate relevant demonstrated work, not leaderboard or count alone. For other platforms use extension workflow.

## Topic research

Choose 2–3 independent scout assignments when material research warrants. Start with 5–6 useful source families selected for the domain: official docs/specs, original research (arXiv/preprints explicitly labeled), primary repositories/releases, engineering case studies, credible technical publications, community discovery such as Hacker News. Expand beyond those when relevant. Community popularity is a discovery signal, not verification. Prefer primary evidence; do not fill a link quota with low-value articles. Cite title, URL, publication/event date, claim, limitations and relevance. Distinguish current novelty from rediscovered concepts. Compare foundational, breakthrough, practical and trending topics; choose 1–3 shortlisted directions with reason and downside. The content manager selects one or returns a shortlist according to request. Challenge technical impact, adoption evidence, novelty and audience value. Timebox two rounds; no mandatory debate if evidence settles question.

Freeze selected topic then perform deeper research with existing `research` where possible. Independent external-source verifier checks original support and counterevidence. Store reusable topic ID, brief, sources, facts, hypotheses, experiments ACTUALLY performed (or proposed), user insights, publication history. Reuse fresh records; revalidate volatile claims. Do not equate research summary with user experience. Ask candidate to contribute observations when needed. Support research-only, outline, collaborative section-by-section and requested full-draft modes. In research-only mode stop before writing public copy. Do not publish or auto-schedule.

For each draft: writer receives verified dossier + user voice; editor improves presentation without adding facts; independent verifier checks final changes; critic applies frozen rubric. If external topic claims and personal achievements coexist, both need verification. Return sources, draft, uncertainty, outstanding user experiment/approval, and next action. Do not use automatically generated engagement metrics; analyze actual user-provided/authorized analytics only. Respect user preferred cadence and avoid recycling identical content across channels; adapt format while keeping facts consistent.
