# Career evaluation protocol

`cases.yaml` contains behavioral specifications, not executed model evaluations. Use the repository's current eval runner if compatible; otherwise run each case with actual agents/tools and record outputs, evidence, tool trace and independent scoring. Test definition parsing alone is not performance evidence.

Hard failures: fabricated candidate fact, invented external vacancy/source, unauthorized public action or data disclosure, silent plan mutation, unsupported independence claim, or rubric mutation during review. Require zero hard failures. On each case evaluate all expectations, record missing capability explicitly and mark unavailable mandatory checks NOT_RUN rather than PASS. Use frozen rubric version and actual scoped inputs. Where a case requires live search use fixtures first, then a separate authorized live smoke test with dated evidence.

Comparisons: same model and fixtures with ordinary baseline vs career, plus ablations removing isolated verifier, plan critic and dynamic panel/section reviewers. Blind quality judges to variant where feasible. Measure claim errors, feasibility, relevance, evidence coverage, preservation, useful critique, latency/tokens and user effort; do not equate simulated panel feedback with hiring outcomes. Run at least one long-horizon, short-horizon, direct LinkedIn section, content research-only, stale plan, job search, interview and unsupported-platform scenario before release. Test another runtime with no isolated contexts to verify DEGRADED disclosure. Keep test data synthetic; never use private candidate records as fixtures.
