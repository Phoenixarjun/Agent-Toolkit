# Interview Intelligence

Load opportunity-and-hiring, workspace, delegation and rubric. Determine prep vs mock vs self-practice quiz, target JD/stage/date, submitted resume if known, actual role/company evidence, time and user preferences. Research actual process only with dated sources; distinguish likely topics, unknown and verified. Don't expose proprietary questions or support unauthorized live interview assistance.

For preparation, use evidence/fit gaps and company report to choose targeted drills, not a generic curriculum. Assign panel roles according to competency and stage: `career-recruiter`, `career-technical-interviewer` (multiple role-specific domain/architecture/coding/commercial contexts), `career-hiring-manager`. Full panel typically 2–4 independent roles; narrow session one appropriate role. Agree competency rubric, question budget and format. Lead owns interactive session: panel proposes question sets, ask one question or agreed batch, wait for real candidate answer, route only relevant response to evaluator, follow-up as needed. Never simulate user responses or prematurely reveal solutions in mock. For technical practice use `teach` only if requested/compatible, not during scored mock unless user switches modes.

Collect assessments independently (no peer scores until final); reconcile by observed competency and evidence, not average across unasked topics. Apply frozen rubric, note NOT_ASSESSED, material errors, strengths and actionable drills; no employer hiring prediction. Use bounded follow-ups, allow pause/stop, record candidate-confirmed outcomes privately if authorized. If no independent contexts, mark DEGRADED. Deliver interview-specific briefing or mock feedback: competencies, actual question/answer evidence, strengths/gaps, prioritized next drills, realistic remaining-time plan and uncertainty. No fictitious completed panel.

## Optional offline practice set

When requested, select only role/stage-relevant competencies and gaps. Use the same panel contracts; assign question author and independent reviewer different contexts. Generate a bounded set (default 5–10 questions, fewer when time is short), mixing single-answer questions for objectively testable knowledge and written prompts for design, coding, behavioral or tradeoff reasoning. Review each answer key, rationale, alternatives, ambiguity and source basis before release; omit uncertain keys or use open-ended criteria. For an opted-in viewer, export a `quiz` block using the viewer DATA-CONTRACT in the Interviews record. Label it self-practice, not a live mock. Reveal answers only on explicit learner action; written responses use criteria and example reasoning for self-review, never model scores in the browser. Candidate can copy responses to an agent for actual feedback; no automatic save/submit, no exam security. If a live mock is requested, do not expose its answer key in advance. Keep generated sets separate from real interview assessments; do not infer readiness from a practice score.
